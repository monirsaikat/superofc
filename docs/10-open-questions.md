# 10 — Open Questions and Working Assumptions

Decisions only the product owner can make. Until answered, implementers use the
**Assumption** column. When answered, move the decision into the relevant doc and strike the
row here. Implementers append new questions at the bottom (section "Raised during
implementation").

| # | Question | Why it matters | Assumption until answered |
|---|----------|----------------|---------------------------|
| Q1 | **Which country's tax and statutory rules ship first?** (e.g., Bangladesh, India, Pakistan, other). Fiscal year start month? | The tax engine is generic, but we need one real country pack, validated against a published example, and the fiscal year drives projections, leave rollover and reports. | Engine ships with a synthetic sample pack only; fiscal year start configurable in first-run (default July). |
| Q2 | **Currency and formatting** — one currency only? Symbol placement, grouping (e.g., 12,34,567 Indian/Bangla style vs 1,234,567)? | `MoneyFormatter` and payslip layout. | Single currency per company; grouping style selectable in Company settings (Western / South-Asian lakh style). |
| Q3 | **Working week default** — Fri off, Fri–Sat off, Sat–Sun off, Sunday only? Half days? | Defaults in first-run wizard and sample data. | Fri–Sat off by default, editable. |
| Q4 | **Payroll frequency** — monthly only, or also weekly/bi-weekly/daily-wage workers? | Daily-wage changes the payable-days and period model. | Monthly only in v1; daily-wage via attendance-linked components (days × rate) inside the monthly run. |
| Q5 | **ZKTeco models and connection** — exact models (K40, F18, U160, MB20, SpeedFace…), firmware, LAN TCP (port 4370) or USB only? Do you have the SDK package? | Determines SDK calls to prioritize, incremental-pull support, face vs fingerprint, and the device test matrix. | LAN TCP with Standalone SDK; both fingerprint and face terminals; `.dat` import for USB-only sites. |
| Q6 | **Enrollment from PC?** Should the app enroll fingerprints with a USB scanner (ZK4500/ZK9500 SDK), or always on the terminal? | Adds another SDK and UI; different licensing. | Enrollment on the terminal only in v1. |
| Q7 | **Scale** — expected employees per installation and number of devices? Largest customer? | Performance budgets and whether SQLite is enough for v1. | ≤ 500 employees, ≤ 10 devices per site. |
| Q8 | **Multiple PCs in the same office now?** (HR on one PC, accounts on another, sharing the same data) | SQLite over a network share is unsafe. If yes, the v2 server (or a small LAN server mode) must move forward. | Single PC in v1; v2 brings multi-user. |
| Q9 | **Languages** — English only for 1.0? Bengali/Hindi/Urdu/Arabic UI later? Payslips in local language? | Font, RTL, resx effort, PDF fonts. | English UI; resx-ready; payslip template supports a second label language later. |
| Q10 | **Overtime policy** — paid for all staff or only some grades? Multiplier (1.5×, 2×)? Weekend/holiday OT different? Approval required? | Payroll engine policies and UI. | OT enabled per employee flag, 1.5× weekday, 2× holiday, no approval workflow in 1.0 (v1.x). |
| Q11 | **Late/absence penalties** — e.g., 3 lates = 1 day deduction? Unpaid leave rules? | Attendance → payroll link (R2). | Policy supports "N lates = X days"; default off. |
| Q12 | **Loans** — interest-free only, or flat interest? Max loan as multiple of salary? Who approves? | Loan engine and validation. | Both none and flat interest supported; default none; Admin/Accounts approve; soft limit warning at 3× gross. |
| Q13 | **Statutory contributions** — provident fund, gratuity, insurance, professional tax? Employer and employee shares? | Components of kind EmployerContribution, reports, year-end. | Generic components only; no statutory report in 1.0. |
| Q14 | **Leave policy** — default leave types and entitlements (casual, sick, earned, maternity…)? Carry-forward? Encashment? | Seed data and R6. | Seed: Casual 10, Sick 14, Earned 18 (editable); carry-forward earned only; no encashment in 1.0. |
| Q15 | **Bank disbursement format** — which bank(s), required file layout (Excel/CSV columns)? | Payment sheet export. | Generic Excel sheet (account, name, amount, reference); bank-specific templates later. |
| Q16 | **Payslip layout requirements** — company logo, signatures, net in words language, one page? | PDF template. | Single page, logo, net in words (English), no signature images. |
| Q17 | **Commercial model** — sold to many companies? License key / activation / trial period / subscription? | Needs a licensing module and possibly a server; impacts update channels. | No activation in 1.0; a `LicenseInfo` placeholder in Settings only. |
| Q18 | **Product name and branding** — final name, logo, accent color? | Namespace rename, installer title, icon. | "SuperOfc" working name; system accent color. |
| Q19 | **Code-signing certificate** — budget for OV/EV certificate (yearly cost)? | Without it SmartScreen warns on install; customers distrust. | Build unsigned betas; signing required before 1.0 (blocks release). |
| Q20 | **Update feed hosting** — public GitHub Releases (free, visible), or private server/S3 (cost, private)? | `UpdateService` source and CI upload step. | GitHub Releases on a private repo with a public release feed, revisit before 1.0. |
| Q21 | **Telemetry / crash upload** — allowed to send anonymous crash reports to a server? | Privacy statement, server cost. | No network telemetry in v1; local diagnostics export only. |
| Q22 | **Data encryption at rest** — needed (SQLCipher) or is Windows account security enough? | Performance and key management complexity. | No DB encryption in 1.0; secrets via DPAPI; recommend BitLocker to customers. |
| Q23 | **Multi-company in one installation** for 1.0? (e.g., an accountant serving several firms) | `CompanyId` is already on every table; UI switcher and reports per company need work. | Single company in 1.0; schema ready. |
| Q24 | **Employee self-service / mobile** — when, and is it a must for v2? | Drives v2 scope: web API, auth, hosting. | v2 includes web self-service for payslips and leave. |
| Q25 | **AI features priority** — which first: natural-language reports, anomaly alerts, document drafting? Cloud model acceptable, or local only? | v3 scope and data-privacy stance (salary data leaving the PC). | Natural-language read-only queries first; cloud provider allowed only with explicit admin opt-in and field-level redaction. |
| Q26 | **Exit handling** — final settlement rules (notice pay, leave encashment, loan recovery from final pay)? | Needs a "final settlement" use case in Phase 4/5. | Loan balance deducted from final payslip up to minimum-net rule; remainder flagged as receivable; no encashment. |
| Q27 | **Attendance correction approval** — can HR correct freely, or does Admin approve corrections? | Workflow in P2-T4. | HR corrects with mandatory reason; Admin sees a corrections report; no approval step in 1.0. |
| Q28 | **Minimum supported Windows** — Windows 10 (which build) or Windows 11 only? | Mica/backdrop fallbacks, testing matrix. | Windows 10 21H2+ and Windows 11; Mica only where available. |

## Raised during implementation
(Implementers add rows here: `| Qn | question | why | assumption used |`)

| Q | Question | Why it matters | Assumption used |
|---|----------|----------------|-----------------|
| Q29 | **Leave year** — calendar year (January to December) or the company fiscal year? | Decides when yearly leave is credited and when carry-forward happens. | Fiscal year (doc 03 R6). One line to change in `LeaveLedger.LeaveYear`. |
| Q30 | **Default leave types** — are CL 10, SL 14, EL 18 (monthly, carry up to 60) and unpaid leave the right starting set? | Seeded for every new company. | Yes (common Bangladesh practice); fully editable in Settings › Leave types. |
| Q31 | **Lunch break deduction** — subtract the shift break always, or only when the person stayed more than half the shift? | Changes worked minutes and overtime for short days. | Only when the stay is longer than half the shift span. |
| Q32 | **Half working day with leave** — does one day of leave on a half working day cost 0.5 or 1 day? | Balance accuracy on Saturdays in some offices. | 0.5 day (the working-day count of that date). |
| Q33 | **ZKTeco SDK licensing** — may we redistribute `zkemkeeper.dll` in our installer, or should we write a managed TCP protocol (port of the open ZK protocol) instead? | The SDK is not in source control; without it devices only work through file import. A managed protocol removes the 32-bit bridge need but costs testing on many firmwares. | Ship the official SDK if ZKTeco's terms allow it (ask the distributor); `IDeviceProtocol` keeps a managed implementation possible later. Release blocked on the answer. |
| Q34 | **Device user ID for pushed employees** — use the number in the employee code (`E0012` becomes `12`) or a separate field on the employee? | Must be unique per device and numeric on most firmware. | Number in the code, unless a link already exists; employees whose code has no number are reported and skipped. |
| Q35 | **Who may sync** — should any signed-in user be able to sync devices, or only HR and Admin? | Automatic sync runs as whoever is signed in. | Sync is allowed for every role because it only reads devices and adds punches; the Devices page and every change need ManageDevices. |
| Q36 | **Payroll before month end** — should payroll be computable before the month is over (for example on the 25th, assuming full attendance for the rest)? | Some offices pay before month end. Projection needs rules for the remaining days and a true-up next month. | Not in 1.0: compute is allowed from the first day after the month. |
| Q37 | **Switched-off components** — should an inactive component still be paid to employees whose salary lists it? | Switching off a component is the usual way to stop an allowance. | No: inactive or deleted components are not paid; the salary keeps the line so switching it back on restores it. |
| Q38 | **Viewer and payroll** — doc 08 P4-T4 says "Viewer can view but not act", but the permission matrix gives Viewer no salary access. Which is right? | Salary is sensitive; a Viewer may be a receptionist or an auditor. | The matrix wins: Viewer sees no payroll. HR can view and compute but not finalize or void; Accounts and Admin can finalize. |
| Q39 | **Void after payment** — may a run be voided while some payslips are marked paid? | Voiding paid salaries usually means money already left the bank. | No: mark them unpaid first, which is audited, then void. |
| Q40 | **Skipped loan installments** — move a skipped installment to the end of the loan, or deduct double next month? | Double deductions can push the next month below the minimum too. | Move it to a new installment after the last one; the loan gets one month longer. |
| Q41 | **Who approves loans** — Accounts and Admin only, or HR too? | HR creates most requests; separation of duties. | HR and Accounts can create, pay out and record repayments; only Accounts and Admin approve, reject or write off. |
| Q42 | **Loan statuses for rejected requests** — keep rejected requests on record or delete them? | Audit and repeat-request history. | Keep them as `Rejected` with the reason; they may be deleted later. |
| Q43 | **Real tax pack (release blocker under Q1)** — which country and fiscal year, and which published example should the pack be checked against? | Only the synthetic `xx-sample` pack ships. Payroll deducts no real tax until rules are entered by hand or a real pack is added. | Ship 1.0 with the synthetic pack and the rules editor; add the first real pack as soon as Q1 is answered, with a test against the published example. |
| Q44 | **Bonuses and overtime in the tax projection** — which pay is "one-off" and counted once, and which is assumed to repeat every remaining month? | Projecting a bonus for every remaining month takes far too much tax; ignoring regular overtime takes too little until the last month. | Taxable one-off adjustments (bonus, arrears) are counted once. Components and overtime are treated as regular pay and projected. |
| Q45 | **Negative true-up** — if too much tax was taken by the last month (for example after an investment declaration), refund through payroll? | Refunds need a negative deduction line and approval. | No refund through payroll; the last month deducts zero and the statement shows the overpayment. |
| Q46 | **More reports for 1.0** — which other reports do offices print every month (for example bank advice per bank, provident fund, tax certificate per employee, attendance register in a statutory format)? | Each is one class now, but statutory formats need the real country (Q1). | Ship the seven core reports plus the existing payroll register, bank and cash sheets, and tax summary. Add others on request. |
| Q47 | **Saved and scheduled reports** — save favourite choices, or email a report every month? | Needs SMTP (v1.x) and a scheduler. | Not in 1.0. The page remembers nothing between visits. |
| Q48 | **Late and absent list range** — is 92 days enough for one list? | Long ranges on large offices make big PDFs. | At most 92 days per run; the summary report covers longer periods month by month. |
| Q49 | **Code-signing certificate** — who buys it (OV or EV) and in whose name? | Unsigned installers trigger SmartScreen warnings; the release checklist requires signed binaries. | 1.0 is blocked on signing; betas stay unsigned. |
| Q50 | **Second UI language** — is Bengali the first translation, and who reviews it? | A scaffold with navigation labels ships; untranslated texts fall back to English and are logged. | Not offered in Settings until a native speaker has reviewed a full translation. Testers can try it with `SUPEROFC_UI_CULTURE=bn`. |
